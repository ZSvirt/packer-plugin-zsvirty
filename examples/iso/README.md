These examples require plugin v0.1.0 or later with `zsvirt-iso` support. Run `packer init` to install the release selected by each template. Supply variables through a local ignored `.pkrvars.hcl` file or `PKR_VAR_*` environment variables, and use the normal `ZSVIRT_*` credentials.

The Debian BIOS boot command loads Preseed from Packer's HTTP server. The auxiliary CD contains `post-install.sh`; Preseed mounts `/dev/sr1` and runs that script in the installer to configure target SSH and completion markers. Change disk/CD device names for your VM hardware. This is an installer script, not a ZSphere userdata payload.

Debian 13's `apt-cdrom` automatically scans all optical drives. The Preseed early command installs an APT generator that temporarily sets `Acquire::cdrom::AutoDetect "false"`, so the answer CD is not mistaken for a package repository. The late script removes that temporary APT configuration. Without this, the installer can stop at an interactive APT media error even though the answer file was read correctly.

Verify the installation ISO against the Debian publisher's checksum before serving its URL. Set `http_ip` to an address reachable from both the VM and image storage. Generated CDs must be downloadable from the runner's temporary publisher port, and the runner must reach the host's TCP VNC console. BIOS/UEFI installers have different boot menus; this example's boot command targets BIOS.

`installation_check_command` verifies the late script's markers and an ext4 root filesystem before and after the builder detaches both ISOs and restarts from hard disk. The example keeps the installation root credential for provisioning; apply your credential removal/rotation and image generalization policy in final provisioners.

Additional answer-file fixtures:

- `windows-server2022/windows-server2022.pkr.hcl`: complete Server 2022 UEFI example with Q35, explicit VirtIO devices, compatibility CPU and Hyper-V optimizations. The ISO/WinRM/reboot/export/new-VM workflow passed in the nested ZStack test environment. Supply signed `2k22/amd64` drivers under a directory named `drivers`; the longer WinRM timeout accommodates slow nested installations.

- `windows11/windows11.pkr.hcl`: complete Windows 11 24H2 UEFI example using an existing ISO, auxiliary answer CD, existing vTPM key provider, compatibility CPU mode and HTTPS/NTLM WinRM. Account and AK/SK authentication are both supported.

- `rocky-amd64/rocky.pkr.hcl`: Rocky Linux 9.4 x86_64 minimal ISO with UEFI by default; set `boot_mode = "Legacy"` for BIOS. The Kickstart file is delivered on the auxiliary CD using `inst.ks=hd:sr1:/ks.cfg`; the Legacy boot command preserves the installer's existing kernel and stage2 arguments, while UEFI loads the ISO kernel and initrd through GRUB. The installer does not fetch Kickstart over the guest network. After installation, the Packer runner still needs a route to the guest for SSH provisioning and hard-disk reboot verification. `http_ip` serves the generated answer ISO to image storage.

- `rocky.ks.pkrtpl`: Rocky Linux 9 minimal ISO, Kickstart over HTTP, root SHA-512 password hash. ARM64 GRUB can load `/images/pxeboot/vmlinuz` with `inst.ks=http://{{ .HTTPIP }}:{{ .HTTPPort }}/ks.cfg inst.stage2=hd:LABEL=Rocky-9-4-aarch64-dvd ip=dhcp console=tty0`, then `/images/pxeboot/initrd.img` and `boot`. Match the ISO volume label and use `boot_mode = "UEFI"` for the ARM fixture.
- `ubuntu-autoinstall.pkrtpl`: Ubuntu Server 24.04 Subiquity autoinstall. Put rendered content in `cd_content["user-data"]`, an instance ID in `cd_content["meta-data"]`, and set `cd_label = "cidata"`. GRUB loads `/casper/vmlinuz autoinstall ds=nocloud ---`, then `/casper/initrd` and `boot`. Connect as `packer` using the password matching `password_hash`. This uses Ubuntu's installer NoCloud reader on the CD; ZSphere userdata is not involved.
- `windows-Autounattend.xml.pkrtpl`: Windows Server 2022 AMD64, UEFI/GPT, image index 2. Provide the installation administrator password as XML-escaped `admin_password_xml` and the reachable runner address as `winrm_client_address`. Put the answer XML at the CD root as `Autounattend.xml`, copy `windows-setup.ps1` as `setup.ps1`, and copy `windows-verify-install.ps1` as `verify-install.ps1`. Add signed Server 2022 VirtIO `viostor`, `vioscsi` and `NetKVM` driver directories under `drivers/`; these external binaries are not committed. The fixture assumes installer CD D: and answer CD E:. Use HTTPS WinRM/NTLM; the setup script restricts the firewall to the runner address. Send Enter after the boot-prompt keys so Windows Boot Manager does not remain paused. Use a root disk of at least 60 GiB and 4 GiB RAM.

For UEFI Debian, GRUB loads `/install.amd/vmlinuz` with the same Preseed arguments, then `/install.amd/initrd.gz` and `boot`; `/install.a64/` is the corresponding Debian ARM installer directory. Set `boot_mode = "UEFI"` and include `test -d /sys/firmware/efi` in the installation check. The Windows verification script checks the firmware through `GetFirmwareType`, the OS caption and AMD64 architecture.

The fixtures intentionally enable installation credentials for acceptance. Supply private values through ignored files, apply your credential policy before distributing images, and perform Windows generalization separately when needed. These fixtures come from packer-plugin-zstack v1.2.1; ZSphere real-cloud acceptance must be run separately for installation, hard-disk reboot, SSH/WinRM, output-template boot, exports and cleanup.

References: [Ubuntu autoinstall delivery](https://canonical-subiquity.readthedocs-hosted.com/en/latest/tutorial/providing-autoinstall.html), [Microsoft unattended setup](https://learn.microsoft.com/windows-hardware/manufacture/desktop/windows-setup-automation-overview), [Windows PE drivers](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-pnpcustomizationswinpe).

For Windows 11, use a platform-supported vTPM with `tpm_key_provider_uuid` referencing an existing key provider and `boot_mode = "UEFI"`. `cpu_mode = "host-model"` corresponds to the platform compatibility CPU mode. Windows optical media require a key during a short boot prompt: use `boot_menu_timeout = "20s"`, `boot_wait = "0s"` and repeated `<spacebar><wait>` entries to cover the prompt. The builder sends these immediately after the start API confirms Running, without another VM polling delay. The Win11 answer file suppresses the product-key UI; it does not activate Windows. Reference: [Microsoft ProductKey UI setting](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-setup-userdata-productkey-willshowui).

The Windows 11 answer file configures language, region and keyboard in both `windowsPE` and `oobeSystem`. WinPE-only locale settings leave the installed system waiting at the OOBE region/keyboard pages, before automatic login can run the WinRM setup script. Keep the `Microsoft-Windows-International-Core` component in `oobeSystem` when adapting this fixture; see [Microsoft's OOBE automation settings](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/automate-oobe).

Windows templates use a guest `shutdown_command` before detaching installation CDs and before imaging the root disk. Keep the 10-second shutdown delay so the WinRM command can return before the service stops. The builder waits for Stopped and does not force power-off on timeout.
